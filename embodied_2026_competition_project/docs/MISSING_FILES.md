## 4. 真实检测、抓放与计分闭环

| 类别 | 原文件/现场信息 | 为什么需要 |
| --- | --- | --- |
| **最终目标清单** | 官方物品名称、颜色、品牌、数量、摆放难度及图片；柜/抽屉位置和把手形式 | 规则举例不等于最终采购，当前 11 类与规则目标不完全对应；不能把类别直接映射难度 |
| 目标模型/验证 | 已训练可用权重、精确标签、实拍测试；必要时原颜色/品牌判别代码 | 确认模型真能识别指定物与相似干扰物，不把未知类别当已实现 |
| 相机环境 | 原 Kinect/RealSense SDK、YOLO/torch 版本、驱动及启动方式 | 主入口彩色检测与实臂内部 RealSense 仍是不同链路，需实际核对 |
| catch_* 对应关系 | 11 标签及新正式目标对应哪些原抓取方法；输入格式、坐标系、尺寸/家具高度 | 原方法不能直接吃二维框或未知标签；无需先升级环境 |
| 深度与标定 | 手眼/相机到臂或底盘变换、TF 时效、可达范围和碰撞约束 | 使重新识别得到的目标成为真实可抓坐标 |
| 真实抓稳/失败反馈 | 原函数返回契约、夹爪/力/视觉等已有证据、超时行为 | 原 catch_* 返回 None；不能把函数结束算成功 |
| 安全收臂/持物/放下 | 已验收的观察姿态、失败收回、导航携物、释放动作及反馈 | 支持失败后复查和停止，不临时编造姿态或开爪 |
| **己方得分区** | 本场抽签决定的门、起始位、1m×1m 区的位置/范围；已有投放落点/掉落判定 | drop 是底盘停靠位，不能证明物品在正确区内；演练无需此反馈 |
| 柜门/抽屉动作（三级） | 若已有：识别把手、开门/开抽屉、安全停止的原代码和参数；若无则明确无 | 当前没有对应接口，不能让模型识别代替物理打开 |
| 实例状态与实测 | 单件 ID、位置/时间、移动/消失关联；分目标成功率、抓放/往返耗时 | 用于去重、两次总尝试、回访与预期得分调度 |

正式主入口的 physical_deliveries 必须由这些真实证据维护；目前没有维护接口，始终为 0，因此会在结束时停车，不自主离场。不能添加配置 confirmed=true 或手动改计数绕过。
