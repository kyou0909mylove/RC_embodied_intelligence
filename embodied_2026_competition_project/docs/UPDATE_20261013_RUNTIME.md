# 2026-10-13 运行故障处理修改

基于 GitHub `main` 的 `c7f49a0`。按本次要求保留设备初始化和初始点/入场点导航的失败出口，将入场后的普通故障留在同一运行会话中处理。

## 明确保留的两处

1. `core/session.py` 的 `_prepare()`、`_prepare_call()` 保持原代码：设备初始化失败仍退出，需要排障后手动 `--resume`。
2. `core/workflow.py` 的 `_initialize_route()` 保持原代码：初始点或入场点导航限次重试后仍失败，继续允许中止。没有实际到达不会更新完成标记。

配置检查、恢复文件校验、同机独占锁、Ctrl+C/主动停止、ROS shutdown、600秒总截止仍保留。第570秒仍优先切换离场。这些是启动条件或明确结束条件，不会转成普通点位失败。

## 入场后的具体变化

| 情况 | 当前处理 |
| --- | --- |
| 运行中 `DeviceUnavailable`、`ParameterFault`、阶段超时或普通异常 | 在 `Workflow.run()` 内处理；停止当前导航，保存状态，等待后重试/继续，不传到 `main.py` 触发资源关闭 |
| 检测点导航设备或参数异常 | 本轮跳过；数量不变，下一轮重新访问，不虚报到达 |
| Kinect采图、模型或连接错误 | 有限重启；仍失败明确记录 `head_vision_degraded`，继续腕部采新图、自主选物；不把故障记为空家具 |
| 识别播报或阶段播报失败 | 记录提醒并返回，不因缺少完成回执终止抓取；初始化语音失败处理不变 |
| 腕部识别或抓取异常 | 当前尝试失败后恢复/跳过；原抓取文件的合爪、补偿和观察位姿不改 |
| 取消目标或收臂持续失败 | 主程序保持运行，等待并自动重试；未收臂时不发下一点位导航，也不伪造 `travel_ready` |
| 投放或弃物释放未确认 | 保留负载状态，继续恢复/重试；不能当空爪开始下一次抓取，不增加交付数 |
| 调度调用异常 | 保留当前内存剩余数量和物品ID，重建后重新应用调用；同一物品ID不会重复扣减 |
| 事件序列化、后台写入异常 | 只记录保存提醒；离场/截止异常继续传递，不被日志容错吞掉 |
| 离场取消、收臂或导航失败 | 在剩余比赛时间内等待重试，600秒结束；离场成功标记只在导航实际成功后设置 |

## 时钟、计数和离场

- 自动恢复不调用新场次初始化，不重置 `started`、570秒离场时间、600秒总截止或剩余数量。
- 故障等待和恢复动作也占比赛时间。单次恢复继续使用原来的阶段限时，超时后外层等待再尝试，避免无限阻塞硬件等待。
- 已保存的释放回执在继续搜索前登记；失败、重复恢复、重复登记不制造抓取或交付分数。
- 离场首先使用“剩余时间减去预计导航时间”的收臂预算。第一次准备失败后继续重试；若已不足预计导航时间，允许利用剩余总时间继续收臂，仍不驾驶未收臂的底盘。
- 第570秒切换离场不等于此刻底盘立即移动；持续取消/收臂故障仍可能导致无法在600秒前到达离场点。
