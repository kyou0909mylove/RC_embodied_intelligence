# 验证报告

验证日期：2026-09-30。环境：Linux / Python 3.12.14，无 ROS 节点、无机器人、无真实相机或模型推理。

执行命令：

```bash
python3 -m unittest discover -s tests -v
```

结果：**53 个测试方法全部通过**。其中部分方法包含多个分支/子用例。使用项目自身的 main() 调度代码，替换的只是 ROS、相机、动作及模型接口；没有用另一份算法来代替主函数进行验证。

| 验证范围 | 已验证的行为 |
|---|---|
| 三种原抓取接口 | table/table_short/ground 均通过；返回 None 不阻止正常流程，也不直接被当作成功 |
| 同类多物品 | 相距 40 cm 的两个同类目标保留独立轨迹，连续交付使用两个不同槽位 |

| 超时后动作 | 抓取返回迟到不继续闭爪/回 home；放置姿态迟到不松爪；松爪迟到不继续回 home 或复核 |

| 地面检测失败 | 观察后未识别到目标时回 home，不调用抓取 |
| 重启与静态检查 | 同局重启在机械臂初始化前拒绝；静态配置检查不连接任何硬件 |
| 配置错误 | NaN、负时间、重叠槽位、三级任务被拒绝 |
| 函数与来源 | 主文件仅 main、无新类/lambda；7 个往年模块原样，3 个仅改4个已有方法体；交付哈希和原方法签名匹配 |

另已进行 Python 语法编译检查。默认 example 配置含待填写项，静态检查返回 2，并逐项列出缺少的坐标、估计、夹爪参数和模型权重，这符合预期。

## 本报告不证明的内容

测试直接执行了两个修复后的 detect_targets 方法体，并使用假模型/假 SDK；没有执行真实驱动、TF、YOLO 推理、相机 SDK 和机械臂运动，不能证明物理可达性、实际抓取成功率、避障效果或比赛得分。测试内的假权重、坐标、相机帧和 action 成功状态仅用于流程验证，不作为部署配置提供。

真实 SIGALRM 测试证明本程序能处理中断模拟的 Python 阻塞调用，不证明任意 C 扩展、驱动或网络故障都能按时中断。硬件看门狗和急停需另行在机器人上验证。

实机必须验证：模型精确标签；两套相机/机器人坐标标定；原三种抓取动作实际适配性；导航目标容差；夹爪阈值；每个槽位的可见性、放置路径、物品完整入区和回 home 路径；启动信号与正式开门时刻的对应；到时底盘/机械臂实际停止行为。

## 第三份工程融合后的新增验证

- 启动信号持久订阅；String/Bool 两种接线均可运行，锁存消息被忽略。
- 同一次 capture 读取两路图像；旧的分开取帧方法在测试中被设置为一旦调用就失败。
- 准备前、导航中和抓取过程中收到 Bool true 停止消息，后续抓取/松爪不再执行；false 不触发停止。
- 原动作内部 action 失败会中止后续序列，不会被最后一次成功状态掩盖。
- 旧物品移入新槽位不新增计数；旧物品无法匹配时不计数；未稳定的基线检测不当作不存在。
- 相机矩阵无效、标定标志未完成、准备上限大于 60 秒、开始和停止话题相同均在硬件连接前拒绝。
- 直接执行两个检测方法体，分别验证无目标、单目标、多候选、NaN 深度、NaN 置信度、NaN 坐标，并检查 pipeline 清理。
- 本轮结构指纹确认3个原模块中只有两个detect_targets及catch_table/catch_table_short方法体改变，没有新增函数或改变签名。
- `python3 main_2026.py --simulate` 实际运行成功：模拟两件同类物品交付并离场，输出明确标记 SIM。

新增附件自身的 40 项测试也曾通过，但它们不是本交付工程的测试计数；历史统一版的40项指其自身的测试方法，不把两套测试简单相加。


## 2026-09-30新增覆盖

本轮53个测试方法全部通过，包括原有40项和13项新增测试；部分方法含多个子用例。原相机失效测试按新策略更新：空爪搜索帧失效受区域访问预算约束，最终不抓取、不计数、不离场；得分区几何失效仍异常停止。

| 新增验证 | 行为 |
|---|---|
| 任务配额 | 两件可见但配额一件，只交付一件；完成后不重复抓取 |
| 连续取物 | 两次抓取之间包含返回搜索区、靠近导航 |
