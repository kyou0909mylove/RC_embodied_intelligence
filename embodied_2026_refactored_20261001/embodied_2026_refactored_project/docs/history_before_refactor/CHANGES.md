# 对两版主函数的修正

A 指之前生成的单文件 `main_2026_embodied.py`，B 指用户提供的 `embodied26_project.zip`。本工程另融合了第三份 embodied26_merged_20260927.zip，具体决策见 MERGE_NOTES.md；不改动用户上传的比较基线。

| 问题 | 本工程的修改 | 实际边界 |
|---|---|---|
| B 的抓取/持物/放置/交付接口返回 UNKNOWN，占位流程无法完成搬运 | 按 A 的实际接口链直接调用三个原 catch_*、夹爪和放置接口 | 原模块与硬件是否适配仍须实机确认 |
| 原 catch_* 返回 None，不能当作失败或成功布尔值 | 独立检查最后 action、多次夹爪反馈、回 home 后反馈、交付图像 | 比赛执行阶段另用 GuardedClient 逐次检查原 action |
| A 未满足夹爪阈值就当作空爪，可能带着物品开始下一次抓取 | 保留 UNKNOWN；任何不明确反馈都会停止，不打开夹爪 | 误报停止会损失时间，但不冒充确定空爪 |
| B 同帧多个检测框累计为多帧命中 | 同帧去重、跨帧一对一关联，每条轨迹每帧最多一次命中 | 仍依赖模型和相机帧质量 |
| B 的约 0.6 m 合并范围会把相距 40 cm 的同类物品合并 | 小范围帧间关联；每次搜索建立新的观察记录 | 空间误差须现场标定；不是完整实例识别 |
| 已交付对象记录可能吸收新物品 | 交付台账与新扫描分离，不将 delivered 记录用于候选合并 | 同类多实例在最终靠近视野中有歧义时跳过 |
| A 重复使用同一落点，却用全局距离去重，真实第二次交付可能永远不计数 | 独立标定槽位、放置前无已识别占用检查、放置后新证据复核、每槽单次使用 | 槽位数量和物品尺寸限制单局容量 |
| B 离场触发与执行最低时间共用阈值，44.9 秒时可能进不了离场 | `exit_trigger_s` 与 `exit_s + margin_s` 分开 | 预算不够则停止，不承诺任何剩余时间都能离开 |
| B 服务/发送目标耗时后可能产生 Duration(0) 无限等待 | 路径查询和发送后再次检查时间，只使用严格正数等待时长 | 下层接口仍可能阻塞，需驱动保障 |
| 原版本可能在截止后继续复核或登记交付 | 单调全局截止、每阶段信号超时、阻塞调用后再检查；迟到结果不登记成功 | 软件层面无法提供硬实时保证 |
| B stop 未取消机械臂/夹爪 | 分别取消导航、机械臂、夹爪并停止底盘；每个接口独立 try | 网络或驱动失联时取消请求不等于已物理停止 |
| B NaN 或负时间可绕过配置 | 全部预算和阈值校验为有限正数，拒绝 bool 冒充数字 | 正确数值仍须实测 |
| 类别名兼作难度、中文名称、模型标签 | 分离区域、level、surface、name_cn、search_label、grasp_label | 同类重叠区域因无法区分归属而拒绝配置 |
| A 用多段最坏超时推算常规成本，过早放弃 | 调度估计与停止超时分开；完成一趟后的实测耗时可上调该区域成本 | 首轮依赖现场估计，无法保证估计准确 |
| done 同时表示完成、失败、没时间 | attempts 保留 RECOGNIZED、DEFERRED_TIME、HOLD_UNKNOWN、DELIVERY_UNVERIFIED、DELIVERED_CONFIRMED 等状态 | 运行日志不是裁判官方计分 |
| 两版重启可能重新取得 600 秒 | 同局 ID 持久标记，在机械臂构造之前拒绝重复启动 | 不实现裁判允许重启情况下的中断恢复 |
| 公共模块存在多份同名代码，可能加载错版本 | 打包 10 个往年模块（8 个原样、2 个检测方法有补丁），校验交付哈希与实际 import 来源 | 如需改原模块，应独立维护和重新验证 |

主函数新增的数据处理、状态判断和配置组织属于调度逻辑；没有补造柜门操作、机器人意图识别、力传感器抓稳判断等底层能力。对于仅凭主函数无法弥补的历史代码问题，在 README 中明确说明。
